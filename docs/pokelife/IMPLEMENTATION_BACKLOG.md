# PokéLife implementation backlog

**Status:** Active delivery plan. It tracks work, not product rules; behaviour belongs in the specifications. Finished work is not recorded here: `CHANGELOG.md` and git history are the archive. **The owner's order from the interview of 15 November 2026 (`evidence/INTERVIEW-2026-11-15.md`) is WORLD team choice, PLAN capture and recurrence, MINT onboarding, CARE, HEAL, BASE, LINK, GEAR**; use it to break ties between rows of equal value.

**How to read this file.** The **Priority board** is the order to work in (pick the first line no other session covers, see CLAUDE.md "Parallel sessions"). The **Register** below it keeps the detail of every open row by ID, in the guide's status vocabulary (Planned, Partial, Blocked); the board points into it and never repeats its numbers. "Not run on a device" applies to every built row. Product rules live in the specifications, not here.

Ranking rule: **value** first (the Bible's module priorities: PLAN, CARE and WORLD are daily and get depth first; MINT, HEAL, BASE and GEAR reach a specialist level; LINK is set once and forgotten; anything that can lose the owner's data or breaks a licence duty outranks features), then **effort**: **S** = a small PR of one session or less, **M** = one session's chunk, **L** = several sessions or a spec first.
