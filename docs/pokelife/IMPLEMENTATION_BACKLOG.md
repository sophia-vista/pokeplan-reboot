# PokéLife implementation backlog

**Status:** Active delivery plan. It tracks work, not product rules; behaviour belongs in the specifications.  
**Created:** 6 November 2026. **Re-checked and re-ordered:** 15 November 2026, at 0.197.0 (rows checked against the code and `CHANGELOG.md`; the guide's "Pending items" list is retired in favour of the board below). The owner's audit of 0.199.0 (15 November 2026, `evidence/AUDIT-0.199.0.md`) is folded in as REP-054 to REP-057 and D9 to D11, with the interview itself filed as `evidence/INTERVIEW-2026-11-15.md`. **The owner's own order from that interview is WORLD team choice, PLAN capture and recurrence, MINT onboarding, CARE, HEAL, BASE, LINK, GEAR**; use it to break ties between rows of equal value.

**How to read this file.** The **Priority board** is the order to work in (pick the first line no other session covers, see CLAUDE.md "Parallel sessions"). The **Register** below it keeps the detail of every row by ID, in the guide's status vocabulary (Planned, Partial, Blocked, Done with evidence); the board points into it and never repeats its numbers. "Not run on a device" applies to every Done row unless a row says otherwise. Product rules live in the specifications, not here.

Ranking rule: **value** first (the Bible's module priorities: PLAN, CARE and WORLD are daily and get depth first; MINT, HEAL, BASE and GEAR reach a specialist level; LINK is set once and forgotten; anything that can lose the owner's data or breaks a licence duty outranks features), then **effort**: **S** = a small PR of one session or less, **M** = one session's chunk, **L** = several sessions or a spec first.
