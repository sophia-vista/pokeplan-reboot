# PokéLife — Shared Assets and Audio

**Version:** 1.0  
**Status:** Authoritative shared asset, rendering and audio specification  
**Last consolidated:** 5 November 2026

> This document owns the shared asset pipeline, asset metadata, visual/audio selection and fallback policy, rendering constraints, provenance and validation requirements. The Product Bible owns product direction; `FEATURES/DESIGN_SYSTEM.md` owns reusable UI component geometry and presentation; `FEATURES/POKEMON_ECOSYSTEM.md` owns canonical Pokémon/species/form identity and owned-Pokémon semantics; module specifications own where and why assets are used. This document must not duplicate those domain rules.

## 1. Purpose and scope

PokéLife uses one shared, PMD-first asset library across the utility modules, WORLD and the optional Android launcher. This specification ensures that the same Pokémon, form, expression, animation and sound resolve consistently wherever they appear, without requiring every species or form to have every asset.

It covers:

- Pokémon sprites, portraits, icons, cries and battle presentation assets.
- World scenery, maps, tilesets, effects, item art and environmental audio.
- Shared UI glyphs and the pixelated PMD dialogue-box visual language.
- Import, normalization, indexing, provenance, licensing, packaging, validation and runtime loading.

It does not define Pokémon ownership, species/form identity, recruitment, evolution, battle stats, module rewards, story content or reusable dialogue-box component behavior. Those remain owned by the Pokémon ecosystem, relevant module/story documents and `FEATURES/DESIGN_SYSTEM.md`.

### 2.1 Known coverage limitations

- Species coverage and form coverage differ by asset family. The main PMD idle set has less coverage than some action sets and portrait strips.
- Portrait strips currently expose Normal, Happy, Joyous, Inspired, Determined and Surprised. Dedicated Sad, Angry, Worried and Teary expressions are not present in the inspected baseline.
- Eat animation is much less complete than idle, sleep, hop and directional walking.
- Cry files are currently species-keyed in `CryPlayer`; do not imply form-specific cries where none are indexed.
- Mainline animated sprite sheets cover only generations 1–5.
- No dedicated Pokémon Ranger asset pack is present in the inspected repository. Ranger media may be considered as a PMD-style fallback only when an exact source, creator credit and rights grant for the intended use are recorded; it is not an assumed available source.
- The current SFX set includes PMD-derived clips whose enum labels were partly assigned by listening/owner identification and partly inferred from duration/pitch. Those uncertain mappings require an audio audit. `assets/pmd-sfx/triggers.tsv` now maps each sound id to the game events that play it (from pret/pmd-red's source), and its README audits the existing guesses: `level-up` was mapped to the dungeon wind sound (216) and now shares the rank-up clip. The rendered `assets/pmd-sfx` clips are a software approximation of the GBA sound engine (no vibrato, reverb or pan; synthesised square, wave and noise channels) and have not been listened to; do not replace a clip ripped from the game with a rendered one without an A/B listen.
- `assets/npc/` contains no production NPC portrait set in the inspected repository. This is not a blocker for the Pokémon-only world premise.

Do not fill these gaps by claiming universal coverage, silently stretching a different form, or fabricating new Pokémon art.

## 3. Canonical identity and asset resolution

All asset lookups begin with the canonical Pokémon identity supplied by the shared Pokémon domain:

- `speciesId`: stable species identity, normally the National Dex number for compatibility with existing source files.
- `formId`: canonical form identity, including regional, gender, cosmetic, battle and special forms only where the Pokémon domain models them.
- `isShiny`: visual variant state where the source actually provides a shiny asset.
- `assetRole`: portrait, idle, walk, sleep, hop, eat, cry, battle still, icon or another explicitly supported role.

Do not use display names, translated names, filenames or regional dex numbers as primary identity keys. Do not create a second species/form catalog in the asset layer. Asset IDs are stable references to media records; they are not Pokémon IDs.

An asset resolver accepts canonical identity plus role/context and returns a resolved asset record, its provenance/license status, and whether it is an exact or fallback match. Callers must be able to distinguish exact coverage from fallback coverage for diagnostics and QA.

## 4. Source hierarchy and fallback policy

### 4.1 Pokémon art

Use this ordered selection policy:

1. **Exact PMD SpriteCollab asset** for the requested species, form, shiny state, role and animation.
2. **Compatible PMD base-species asset** only when the form's visible distinction does not make the substitution misleading. This is an explicit per-form compatibility decision, never a global assumption.
3. **Permitted Pokémon Ranger asset** where a suitable asset has actually been sourced and its individual rights are cleared. Ranger is a potential fallback family, not part of the inspected 0.123.0 asset inventory.
4. **Permitted mainline/PokeAPI or Pokémon Showdown still asset** for the same species/form where available and legally usable for the intended distribution.
5. **Existing compatible PMD static frame** from the same Pokémon/form, held without invented movement, where the requested use allows a still.
6. **Text-only or neutral UI fallback**: species/form name, accessible label, empty portrait slot omitted, or a standard module/item icon. Do not substitute unrelated Pokémon art.

A source being present in the repository does not make it eligible for a public build. Resolver candidates must be filtered by the release's rights policy before selection.

### 4.2 Animation-specific fallbacks

- Missing walk direction: use the closest available direction only if it does not create obvious backwards movement; otherwise use a static idle frame.
- Missing idle: use the best compatible static front frame. Do not borrow another species' idle.
- Missing sleep/hop/eat: show a still pose or omit the action. Do not synthesize motion by repeatedly flipping, scaling or deforming a still.
- Missing battle animation: use a compatible static sprite/portrait and standard battle feedback effects; do not imply a move animation exists.
- Missing shiny: use the normal appearance only when the UI does not explicitly promise shiny rendering; otherwise preserve shiny metadata and show a clear non-art fallback rather than displaying a false shiny.

### 4.3 Portrait expressions

Preferred order: exact form + requested expression; exact form + deliberately mapped closest expression; compatible base-form portrait; omit portrait and retain dialogue/name. Current supported expression set is `Normal`, `Happy`, `Joyous`, `Inspired`, `Determined`, `Surprised`.

Expression mapping is semantic, not random. Example mappings may map a low-intensity worried beat to `Surprised` or `Normal`, and sadness to `Normal` when no truthful face exists. Angry or tearful story beats should use dialogue/scene staging rather than a misleading happy portrait. Store mappings centrally and review them with narrative QA. Never recolor or redraw a portrait to manufacture an emotion.

### 4.4 Icons and non-Pokémon UI

- Use the assigned helper Pokémon sprite only where the module's own specification explicitly allows it. GEAR helper Pokémon are visual-only; tools remain fully usable without them.
- Use PMD item icons for item/tool identities where that is the established module convention.
- Use Pixelarticons only for simple controls (add, edit, close, delete, arrows, copy, play/pause, etc.). They are not Pokémon, item or decorative art substitutes.
- Do not mix unrelated icon families or add generic icons where the product has an assigned helper/item identity.
- When no appropriate asset exists, use a text label or a standard shared system icon rather than an unrelated Pokémon.

## 5. Asset classes and content standards

### 5.1 Overworld and roaming sprites

- Prefer PMD idle and directional walk assets.
- Preserve each source frame's crop, transparent padding and per-frame dimensions as recorded by its metadata. Do not normalize by stretching individual frames to a shared rectangle; render them into a consistent logical cell with a stable foot/baseline anchor.
- Keep left/right direction handling explicit. If mirroring a right-facing walk for left is used, record that in the manifest and verify asymmetric details do not become incorrect.
- Animation frame order and per-frame duration come from source metadata or reviewed animation definitions. Avoid assuming all animations loop at the same speed.
- Roaming should use a small number of concurrent actors, bounded update rates and pause behavior defined by WORLD/launcher. Do not continuously animate off-screen Pokémon.

### 5.2 Portraits

- Portrait strips are indexed by form and expression metadata, not hard-coded frame positions in story code.
- The resolver returns a crop/frame descriptor and expression availability.
- Keep portraits crisp and at their intended relative scale. Never use a full portrait strip as a single image.
- If a portrait is unavailable, the dialogue panel must remain correctly laid out without a broken image placeholder.

### 5.3 Icons, items and status assets

- Preserve the transparent source canvas and authored pixel bounds.
- PMD item assets keep their original identity and mapping; do not repurpose an item to represent a different mechanic.
- Status/weather/effect strips must retain frame boundaries and timing metadata.
- Small UI glyphs should be rasterized from their vector source at the intended 24 px source grid with no antialiasing, then tinted only as permitted by the original asset format and license.

### 5.4 Battle and scene assets

- Use existing scene backdrops and battle stills when the scene context calls for them.
- Keep Pokémon battle presentation tied to the canonical species/form and move/battle data; do not treat decorative backdrops as battle sprites.
- A static scene is a valid fallback. Motion and effects are optional polish, not a gameplay requirement.
- WORLD's scene engine owns scene composition and event timing; this document owns how media is found, validated and rendered.

### 5.5 Dialogue frames, borders and pixel components

- PMD dialogue-box geometry, corner treatment, outline weights, surface colors, shadows, sizing, typography roles and nine-slice behavior are defined only in `FEATURES/DESIGN_SYSTEM.md`.
- Existing PMD dialogue frames are primarily code-drawn in the current repository. Continue using shared Compose components and centralized tokens; do not introduce per-module image borders or separate panel skins.
- If a bitmap frame is adopted, it must be a neutral, rights-cleared UI component, sliced/nine-sliced so corners and edge pixels remain intact. It must pass light/dark, font-scale and dynamic-content tests.
- Use the PMD bitmap dialogue font only in contexts where its glyph coverage and license permit. Unsupported glyphs fall back to a readable system font (the current launcher uses Nunito fallback). Do not render long utility content in bitmap type.
- UI chrome may be drawn in code; Pokémon, item and world art must be sourced media with recorded provenance. No hand-drawn, generated or procedural replacement Pokémon pixel art.

## 6. Audio content and playback policy

### 6.1 Audio categories

Maintain separate logical channels:

- **UI SFX:** cursor, confirm, back, error and restrained interaction feedback.
- **Gameplay SFX:** item, level, rank, hatch, evolution and meaningful World event effects.
- **Pokémon cries:** species-associated vocalization, not a generic tap response.
- **Ambient/environment:** optional town, habitat, dungeon and weather ambience.
- **Music:** optional scene/background music only where the source and license permit it.

The current common interface is `CryPlayer.play(speciesId, volume)` plus `CryPlayer.effect(sound, volume)` and the shared `Sfx` enum in `composeApp/.../ui/Cries.kt`. Android currently uses `AndroidCries.kt`; web uses `WebCries.kt`; the desktop/JVM build has no OGG player. Missing files must remain silent and never crash. Preserve platform capability differences explicitly; do not promise audio support where no backend exists.

### 6.2 Selection and fallback

- Resolve cries by canonical species ID; current implementation does not expose form-specific cry identity.
- Play the real cry only when the species ID has a valid mapped file. Missing cry means silence, not a substitute species cry.
- Use SFX only for the event represented by the enum; correct mismapped clips rather than renaming the event to fit an arbitrary sound.
- Missing SFX is silent and does not block the underlying action.
- Do not add audio merely because an asset exists. Each sound needs a documented trigger and a reason it improves feedback.

### 6.3 Playback behavior

- Sound is optional and context-aware. Provide independent controls for UI/game SFX, Pokémon cries, ambience and music; a master mute is also available.
- Volume is user-adjustable per channel. Keep UI tap gain restrained; current `TAP_GAIN=0.06f` is an implementation baseline, not a universal mandated level. Validate it on-device and avoid duplicate sounds for one action.
- Do not overlap repeated cries, stack multiple reward jingles or let ambient loops compete with speech/dialogue. Use a small priority/ducking policy: spoken/dialogue content and critical feedback take precedence; repeated low-priority ambient/idle sounds are dropped or paused.
- Respect Android audio focus, ringer/DND expectations and system media volume. Do not force playback on app launch, screen unlock or notification delivery.
- Pause or release ambient/looping audio when the app/launcher/World scene is backgrounded, hidden, minimized, screen-off or disposed. Resume only when the owning surface is visible and the user has enabled that channel.
- Avoid continuous cries, repeated idle barks and sounds triggered by recomposition, polling, scrolling or every touch in a gesture.
- Notification sound is controlled by Android notification channels and the shared reminder/notification policy, not by an in-app SFX player. Do not play the same alert through both channels.
- Audio never carries essential information alone. Pair important events with visible state and accessible text; no sound is required to complete a task.

### 6.4 Accessibility and motion

- Provide visible/accessible equivalents for every sound-only cue.
- Respect app mute, system settings and any relevant accessibility settings. Sound is off when the user disables it; no nagging prompts to re-enable it.
- Reduced Motion is separate from sound. A user may keep sound while reducing animation or vice versa.
- No timed interaction or critical state depends on hearing a cry/SFX.
- Avoid abrupt high-volume peaks, startling repeated sounds and unnecessary loudness normalization changes. Audit levels across all clips.

## 7. Naming, directory organization and metadata

### 7.1 Directory structure

Retain existing directories during migration to avoid breaking code. New canonical metadata should describe them independently of their physical path. The intended logical organization is:

```text
assets/
  pmd/                 # SpriteCollab source media and legacy TSVs
  cries/               # species cry files
  sfx/                 # UI/game SFX
  sprites/             # mainline still fallbacks
  animated/            # legacy mainline animated sheets
  portraits/           # future normalized portrait registry target
  scenes/              # scene/battle backgrounds
  world/               # PMD maps, locations and effects
  tiles/               # dungeon/overworld atlases
  pmd-items/           # PMD item icons
  pixelarticons/       # UI glyphs only
  status/ weather/ fonts/ backgrounds/
  manifest/            # normalized asset registry and generated reports
```

This is a logical target; do not move or duplicate existing large media solely to match the diagram. A future migration may reorganize files after all code paths and build packaging are covered by tests.

### 7.2 Naming

- New canonical asset IDs use lowercase kebab-case with explicit role and identity, e.g. `pokemon-0025-pikachu-form-default-pmd-idle-front` or `pokemon-0025-pikachu-form-default-portrait-happy`.
- Use stable IDs rather than source filename as the primary key.
- File names should be deterministic and collision-free; avoid localized names and ad hoc abbreviations.
- Preserve upstream filenames in source metadata and record the transformed packaged path separately.
- Existing numeric filenames (e.g. `assets/cries/25.ogg`, PMD species-number files, `pmd2-001.png`) remain supported until the resolver migration is complete.

### 7.3 Normalized manifest

Create a generated, version-controlled manifest (JSON/TSV is acceptable; JSON is preferred when nested frame/crop metadata is needed). Each record should support:

| Field | Requirement |
|---|---|
| `assetId` | Stable unique ID |
| `assetType` | sprite, portrait, icon, item, tileset, background, effect, cry, sfx, music, font |
| `speciesId`, `formId` | Optional canonical Pokémon references |
| `role`, `direction`, `expression`, `animation`, `shiny` | Optional typed visual/audio descriptors |
| `sourceName`, `sourceUrl`, `sourceCommit` | Exact upstream identity and pinned revision |
| `authorCredits` | All known creators/contributors; preserve source credits tables |
| `licenseId`, `rightsStatus`, `commercialAllowed`, `redistributionAllowed` | Explicit rights state; unknown is not allowed |
| `originalPath`, `packagedPath` | Source and transformed locations |
| `sha256`, `fileSize`, `mimeType`, `width`, `height`, `frameCount` | Integrity and technical metadata where applicable |
| `frameDurations`, `cropBounds`, `anchor`, `tileSize` | Animation/render metadata where applicable |
| `derivedFrom`, `transformScript`, `transformVersion` | Reproducible processing lineage |
| `fallbackAssetId`, `fallbackPolicy` | Explicit fallback link/rule where useful |
| `tags`, `notes`, `reviewStatus` | Search, caveats and human QA |

Use `rightsStatus` values such as `approved`, `private-use-only`, `non-commercial`, `permission-required`, `unknown`, `rejected`. Only assets marked approved for the current target distribution may enter that release package.

### 7.4 Versioning

- Pin upstream Git repositories to immutable commit hashes, not `main`/`latest` branches.
- Store fetch/extract scripts and transformation versions in the repository.
- Record source updates as manifest changes with checksums and a generated coverage diff.
- Never silently overwrite an asset with a new upstream version; keep a traceable change and verify credit/license changes.
- Version the manifest schema. Migrate it with code and tests; asset updates must not change canonical Pokémon identity or owned Pokémon records.

## 8. Resolution, scaling and animation

- Preserve source pixel dimensions and native frame pixels. Do not smooth, blur, antialias, add glow or upscale with bilinear/bicubic filtering.
- Use nearest-neighbor sampling for pixel art. Prefer integer scale factors when practical; where screen density requires fractional layout size, render to a logical pixel surface and inspect for uneven pixel widths/shimmer.
- Separate logical game pixels from Android dp. Compose layout controls placement/size; a pixel renderer controls nearest-neighbor sampling and camera scaling.
- Use integer-aligned coordinates and stable sprite anchors. Avoid fractional translation where it causes shimmer.
- Nine-slice bitmap dialogue frames only when permitted and when `DESIGN_SYSTEM.md` requires it; do not stretch corners.
- Keep animation timing in metadata/animation definitions. Use source timing when available, otherwise define reviewed per-animation timing rather than a universal frame delay.
- Use bounded frame rates. Idle ambient motion can be throttled; pause off-screen and background animations. Respect Reduce Motion and battery saver.
- Avoid loading a whole species library into memory. Load only the visible collection/party/scene and immediate next scene assets.
- Sprite frame order, facing and mirroring must be deterministic. Animation must not alter gameplay state or grant rewards.

## 9. Import pipeline and tooling

The asset pipeline is an offline, reproducible build-time process:

1. **Source registration:** add source repository/URL, commit, license and attribution record before fetching.
2. **Fetch:** deterministic scripts download only the approved upstream paths; no runtime downloads.
3. **Transform:** crop, convert, rasterize or encode with scripts checked into `tools/`; preserve original inputs or source references where redistribution rules allow.
4. **Metadata:** generate/update normalized manifest and retain upstream TSVs/credits.
5. **Validation:** run structural, identity, rights, image, audio and coverage checks.
6. **Review:** inspect contact sheets, expression maps, animation loops, audio mappings and release rights.
7. **Package:** include only assets allowed for the build target; separate private development assets from redistributable artifacts.
8. **Runtime:** resolve through one shared asset registry/loader, with bounded caches and deterministic fallbacks.

Required validation commands should be available through a single documented Gradle task or script entry point (exact task name is implementation-defined):

- Verify every manifest path exists and every packaged asset is referenced.
- Detect duplicate IDs, path collisions, missing files, empty files and checksum drift.
- Parse TSV/JSON and validate species/form IDs against the canonical Pokémon catalog.
- Compare expected species/form coverage with each asset family; report exact, fallback and missing counts separately.
- Validate animation frame counts, crop bounds, frame durations, transparent bounds and dimensions.
- Verify PNG decode, alpha channel and expected image dimensions; reject accidental resampling or color-depth changes where prohibited.
- Decode OGG files, verify duration/sample rate/channels, detect zero-length/corrupt audio and flag peak/loudness outliers.
- Verify every SFX enum entry maps to a file and every cry mapping resolves to a file or an explicit missing record.
- Verify attribution/license metadata is complete and release eligibility is satisfied.
- Generate machine-readable reports plus human-readable coverage summaries and contact sheets/audio audition lists.

A missing optional animation is a warning, not a build failure. Missing required manifest data, invalid IDs, broken files, unknown rights in a release package, or a missing mandatory fallback is a build failure.

## 10. Provenance, licensing and distribution

PokéLife's existing asset collection contains several different rights categories. Never treat the license of a repository, API, tool or extraction script as the license of the artwork/audio it contains.

| Asset family | Existing source evidence | Policy |
|---|---|---|
| PMD SpriteCollab | `PMDCollab/SpriteCollab`, pinned `cf6c95f`; `pmd.tsv`, `credits.tsv`, portrait TSVs | Current repo documents CC BY-NC 4.0 with creator credit. Preserve per-asset artist credits. Non-commercial restriction means no commercial distribution under that grant. Verify exact upstream terms and any underlying game-art rights before release. |
| Mainline sprites / cries | PokeAPI sprites and cries repositories | Pokémon/Game Freak media; current project docs classify as private use only. PokeAPI hosting does not grant redistribution rights. |
| Black/White animated sprites | PokeAPI/sprites | Game Freak art; private use only in current docs. |
| Showdown scenes | Pokémon Showdown client `fx` assets | Art by Showdown contributors but Pokémon-derived; current docs classify as private use only. Audit each asset's terms and underlying rights. |
| PMD world/tiles/item/status/weather assets | Game rips supplied by owner and Spriters Resource contributors | Game-derived media; current docs classify as private use only. Preserve contributor credits/notes; no public redistribution without rights. |
| PMD cries/SFX and game fonts | Game Freak/Chunsoft audio and fonts | Private use only in current docs unless separate rights are obtained. |
| Pixelarticons | `halfmage/pixelarticons`, pinned `c9ecc2d` | MIT for the icon package; preserve its license and attribution notice. This does not grant rights to Pokémon/game artwork. |
| Pokémon-DP font package | `hexparrot/pokemon-assets` / upstream fork | Package license noted as MIT, but recreated game fonts and embedded art still require separate rights review. Keep package and artwork rights distinct. |
| Code-drawn UI chrome | PokéLife source code | Project-owned implementation; still must follow `DESIGN_SYSTEM.md` and avoid copying protected game screen art. |

**Release gate:** the inspected repository is documented as a private project and includes non-commercial and private-use-only material. It is not currently cleared for public distribution or monetization. Before any public release, produce a rights audit for every packaged asset, obtain permissions or replace/remove restricted media, and confirm redistribution and commercial rights at the individual asset/source level. A private build is not automatically legally cleared; follow the owner's distribution decision and applicable law. Do not publish a raw SpriteCollab/game-rip asset pack or imply the source project grants those rights.

Each visible asset credit should be available from an in-app credits/about screen or a documented credits file. Where per-artist attribution is required, expose the actual creator list from metadata, not a generic “SpriteCollab” credit alone.

## 11. Performance and storage

- Keep source archives and extraction-only intermediates out of runtime APK/AAB assets.
- Deduplicate identical files by checksum where licensing permits; do not create duplicate copies per module.
- Prefer compressed PNG/WebP only if conversion preserves exact pixel colors and alpha and does not violate source/license terms. For pixel art, validate lossless output; do not use lossy compression.
- Use OGG for audio where current platform support is reliable; keep clips short and mono where appropriate, but do not alter source audio in a way that harms quality or attribution.
- Lazy-load sprites, portraits, tiles and audio. Preload only the current scene/party and immediate transition assets.
- Use bounded LRU caches for decoded bitmaps and audio resources; release on lifecycle/scene disposal. Avoid caching every species or all frames at once.
- Avoid per-frame full-scene recomposition. Keep animation updates scoped to active sprites/effects.
- Pause animation, ambience and weather-related rendering when hidden/backgrounded; use adaptive quality and battery-saver modes.
- Report packaged asset size by category and monitor growth in CI. Large optional libraries should be split into packs or omitted from targets that do not use them.
- All essential functionality and asset resolution must work offline. No asset fetch is required during normal use.

## 12. Module usage boundaries

| Area | Asset/audio use |
|---|---|
| PLAN | Restrained UI feedback and optional reward/event sounds; no Pokémon decoration that slows task capture or Focus. |
| CARE | Buddy/visitor sprites and portraits where specified; sound/reaction only after a meaningful explicit interaction. Never use sensitive diary content to select art/audio or expose it outside CARE. |
| HEAL | Pokémon presentation is supportive and optional; health records/measurements remain readable and are never conveyed by sound or animation alone. |
| MINT | Minimal helper/icon use; no noisy reward presentation around balances, transactions or financial alerts. |
| HOME | Pokémon discovery visuals may appear in the approved discovery flow; avoid decorating household records. |
| LINK | Relationship/contact data remains user-controlled; Pokémon art is only presentation, not an indication of another person's status or intent. |
| GEAR | Helper Pokémon are visual-only tool identities; normal tool/item icon fallback; no helper requirement, acquisition or rewards. |
| WORLD | Highest asset intensity: portraits, overworld sprites, scenes, maps, tilesets, battle effects, cries and SFX. Story engine owns timing; shared resolver owns asset selection. |
| Launcher | Living-town sprites, directional walking, optional ambient cries/SFX and environment art; pause when hidden/backgrounded and honor user population/performance settings. |

Module specifications may define their own contextual trigger and visibility rules. They must not duplicate asset catalogs, provenance records, fallback algorithms or global audio settings.

## 13. Acceptance criteria

The shared asset/audio system is acceptable when:

- [ ] All Pokémon asset lookups use canonical species/form identity and stable asset IDs.
- [ ] Coverage is reported per asset family and per form; missing animation is not misrepresented as full coverage.
- [ ] Exact PMD assets are preferred; fallback order is deterministic and rights-filtered.
- [ ] Missing animation uses a truthful still/omission fallback; no fabricated Pokémon art or movement is introduced.
- [ ] Portrait expression fallback is centrally mapped and story-reviewed.
- [ ] Cries resolve by species without inventing form-specific coverage; missing cries are silent.
- [ ] Every SFX enum maps to an audited, correctly labeled sound or an explicit silent fallback.
- [ ] UI chrome follows `FEATURES/DESIGN_SYSTEM.md`; pixel dialogue borders remain consistent across modules and World.
- [ ] Pixel art is nearest-neighbor rendered, anchored consistently and visually checked at target densities.
- [ ] Animation is lifecycle-aware, reduced-motion-aware and battery-conscious.
- [ ] Audio has independent volume controls, no unintended overlap/duplicates, and accessible visual equivalents.
- [ ] Every packaged asset has source, creator/attribution, license, checksum and rights status recorded.
- [ ] Release packaging excludes assets not cleared for that distribution target.
- [ ] Automated validation detects missing files, broken metadata, corrupt media, missing mappings and rights failures.
- [ ] Runtime loading is offline, lazy and bounded in memory; no full-library decode or background rendering loop.
- [ ] Module-specific specs reference this document and do not fork its shared rules.

## 14. Implementation priorities

### P0 — establish safe shared foundation

1. Add normalized asset manifest schema and generate it from existing PMD TSVs, `assets/sprites/manifest.tsv`, item manifest and source notes.

## 16. Change control

- Changes to asset schema, source hierarchy, rights policy, renderer sampling or global audio controls belong here first.
- Changes to dialogue-box geometry, border tokens, typography or shared component appearance belong in `FEATURES/DESIGN_SYSTEM.md` first.
- Changes to species/form identity, Pokémon ownership or shared collection semantics belong in the Pokémon Ecosystem specification.
- WORLD, launcher and module documents link here and specify only their own asset use, trigger and presentation context.
- Update `docs/assets.md`, this document, generated manifests and validation tests together when the repository inventory or upstream sources change.
