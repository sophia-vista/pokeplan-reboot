# PokéLife (reboot)

**`docs/pokelife/` is the source of truth** for what PokéLife is and what to build (owner, 6 November 2026): start at `docs/pokelife/README.md`, then the Product Bible and the module or feature spec you are touching. `docs/design.md` and `docs/economy.md` describe what the code does today and are evidence, not authority; where they disagree with `docs/pokelife/`, it wins, and a rule changes in the owning `docs/pokelife/` file first. Decisions already made there: Android is the only product platform (desktop and web are dev conveniences that gate nothing); local-only has priority (no new Supabase, account or sync work; they are retired after the migration gates); the modules are PLAN, CARE, HEAL, MINT, BASE (renamed from HOME, 13 November 2026), LINK, GEAR and WORLD (no Grow, no Explore); one currency, Poké; and a Pokémon in **one place only** (7 November 2026): the global buddy (the main companion, cosmetic), a party of one lead and five per module (its bonuses apply to that module only), a Guardian slot, a WORLD expedition team, a GEAR helper (visual only), or the PC (`Places` in app-core; every assignment takes the Pokémon from its old place). `docs/pokelife/IMPLEMENTATION_BACKLOG.md` is the work list.

The app is **PokéLife** (renamed from PokéPlan in 0.47.0; PokéPlan is now the name of its Plan module). Code packages (`app.pokeplan.*`), the repository, the Android application id and the save keep the old name. A fun productivity, growth and self-improvement app for Pokémon lovers: finishing a focus timer hatches an Egg, finishing tasks, habits and goals earns candies and items that level up and evolve Pokémon. The repo holds two codebases:

- **The rewrite (repo root):** Kotlin Multiplatform (Android, desktop, web), local-only (the Supabase backend was retired in 0.130.0). `docs/pokelife/` says what to build; `docs/design.md` records the game rules the code implements today. Read the relevant `docs/pokelife/` spec before changing game rules, and update it (and `docs/design.md` when the code changes) when a rule changes. Numbers marked *(tune)* there are starting values.
- **The original app (`legacy-android/`):** a native Android Java app from a MOBDEVE pair project, kept as the reference for the old rules. It is no longer developed.

## Layout
**Detail for every line below is in `docs/code-map.md`: grep it for the module before touching one (storage tables, schema numbers, sealing, key classes).**
- Rule modules (Kotlin Multiplatform, JVM and wasmJs, no UI): `pokemon-core/` (Dex, reward engine, owned Pokémon; knows nothing about tasks), `plan-core/` (focus, tasks, recurrence, goals, review), `care-core/`, `heal-core/`, `mint-core/` (exact integer money), `base-core/`, `link-core/`, `world-core/` (`docs/pokelife/MODULES/WORLD.md`). A life module knows nothing about Pokémon or rewards: its store in `app-core` pays through the `World` interface with a minimal event (`CareEvent`, `HealEvent`, `MintEvent`, `BaseEvent`, `LinkEvent`) that never carries a figure, a name or a private word.
- `app-core/`: the rules engine with no UI. `GameStore` applies every user action and saves one `AppData` through a `Storage`; each life module has its own store (`CareStore`, `HealStore`, `MintStore`, `BaseStore`, `LinkStore`). Tests: `./gradlew :app-core:jvmTest`.
- `data/`: the local SQLite database (SQLDelight, Android and JVM only), live on Android since 0.129.0. `LiveDocuments` splits the save into per-module tables (`plan_*`, `care_*`, `heal_*`, `mint_*`, `home_*`, `link_*`, the Pokémon, Bag and ledger tables) and puts it back together on a read. **A schema change needs a numbered `.sqm` migration and the released schema committed in `databases/N.db`. Heal and Mint rows and every backup of them are sealed (AES-256-GCM, Android Keystore) and fail closed without the key: never write them unsealed, never log them.** Desktop and web keep JSON stores. Tests: `./gradlew :data:jvmTest`.
- `composeApp/` (shared Compose UI, `app.pokeplan.ui`, one package per module, `App()` is the entry) and `androidApp/` (thin Android app, widgets and the app share one save): layout, menus, buddy and background rules are in the `compose-ui` skill. Load it before touching either.
- **No cloud (0.130.0):** no Supabase, accounts, sync or server; rewards are decided on the phone. Do not add any.
- `assets/`: real game assets, listed with sources and licences in `docs/assets.md`; how each is fetched is in the `game-assets` skill. `legacy-android/`: the old Java app, see the `legacy-android` skill.
- Docs: `docs/pokelife/` (authority), `docs/design.md` (rules the code implements), `docs/economy.md` (every reward source, sink and cap, under `RewardRules.VERSION`: bump it, and update that file, with any rule that changes what an event pays).
- **Art rule (owner's): use real game assets only (PokeAPI/sprites, Showdown) and the PMD SpriteCollab sprites, which are the preferred Pokémon sprites (CC BY-NC 4.0: non-commercial, credit the artists); never hand-draw, generate or procedurally draw pixel art.** **Which art goes where (owner, 14 November 2026; `docs/pokelife/FEATURES/ASSETS_AND_AUDIO.md` 4.0):** Pokémon sprites and portraits are PMD first, with mainline Generation 5 style as the fallback; PMD concepts, places and tilesets are for WORLD and the launcher only; the modules use mainline assets, mostly Generation 3, or whatever fits the 2D pixel look. UI chrome (panels, buttons, bars) is drawn in code; icons and sprites are always real assets.
- **Versioning:** `VERSION` at the repo root (`MAJOR.MINOR.PATCH`, below 1.0 a feature bumps the minor and a fix the patch) is the single source. Gradle turns it into the Android `versionName` and the generated `AppVersion` shown in Settings → About; the release workflow also passes its run number as `POKEPLAN_BUILD` (the Android `versionCode` and "build N"; without it the app says "dev"). `release-apk.yml` publishes the rolling "Latest build" and, the first time a `VERSION` is seen, that version's own `vX.Y.Z` release. Bump `VERSION` in the PR that ships something and add it to `CHANGELOG.md`.
- Signing: every build (local and CI) uses the committed `androidApp/pokeplan-debug.keystore` (alias `pokeplan`, password `pokeplan`), SHA-1 `1A:28:99:CD:34:46:02:04:1E:AF:7B:15:7F:D1:07:41:BC:30:F0:A5`, so the app signature is stable. Private repo only; TODO before any public release: move to a secret key.

## Commands (rewrite, from the repo root)
- All tests (JVM): `./gradlew jvmTest`; one module: `./gradlew :pokemon-core:jvmTest`; one class: `./gradlew :pokemon-core:jvmTest --tests "app.pokeplan.core.EggTest"`
- Compile the web target: `./gradlew compileKotlinWasmJs` (wasm tests need yarn and a browser and are not run here)
- Regenerate Dex data: `python3 -I tools/species/generate.py`
- The golden vector (`pokemon-core/src/jvmTest/resources/golden.json`, checked by `GoldenVectorTest`): regenerate with `UPDATE_GOLDEN=1 ./gradlew :pokemon-core:jvmTest --tests "*GoldenVectorTest*"` after a deliberate rule change (and bump `RewardRules.VERSION`).
- **Actions are used sparingly (owner's rule, 6 November 2026):** `ci.yml` runs on a PR only with the `ci`, `android` or `apk` label (or by hand); a PR touching only `docs/`, `.md` files, `.claude/` or `legacy-android/` is not tested. The local `./gradlew jvmTest compileKotlinWasmJs` is the normal gate. Full CI and release-workflow detail: `ship-pr` skill.
- World economy simulation: `./gradlew :world-core:simulateWorldEconomy` writes `docs/world-economy-report.md` (floors, jobs, facilities, Café, Swap Shop, Dojo, shop over a year); re-run it after changing any World number.
- Economy simulation: `./gradlew :plan-core:simulateEconomy` writes `docs/economy-report.md` (about 1 to 2 minutes). Re-run it after changing any reward, rank, egg, candy or transfer number and compare with the pacing targets in docs/design.md.
- Android app: `./gradlew :androidApp:assembleDebug` (APK in `androidApp/build/outputs/apk/debug/`). Its tests (Robolectric on the JVM, REP-033: `LiveStore`, sealing with `FakeAndroidKeyStore`, reminders, receivers, widgets' save): `./gradlew :androidApp:testDebugUnitTest`; run them after touching `androidApp/` or an `androidMain` source set (they are not part of `jvmTest`). Desktop: `./gradlew :composeApp:run`. Web: `./gradlew :composeApp:wasmJsBrowserDevelopmentRun`. Compile checks without a display: `./gradlew :composeApp:compileKotlinJvm :composeApp:compileKotlinWasmJs`.
- Gradle 9.8.1, Kotlin 2.4.21, AGP 9.4.1, Compose Multiplatform 1.12.2, any JDK 17 to 21.
- In the cloud sandbox: `dl.google.com` (Google's Maven and the Android SDK) must be in the environment's allowed domains. The SessionStart hook (`.claude/hooks/session-start.sh`, cloud sessions only, no tokens spent, runs in the background) installs the SDK to `~/android-sdk` (cmdline-tools, `platform-tools`, `platforms;android-37.0`, `build-tools;37.0.0`), writes `local.properties`, and adds a Gradle init script in `~/.gradle/init.d` that tries `https://maven-central.storage-download.googleapis.com/maven2` first, because Maven Central rate-limits the shared proxy. **Before the first Gradle command of a cloud session, run `.claude/hooks/wait-for-setup.sh`**: it returns at once when the hook is done, waits while it runs, and says so if it failed (then run the hook by hand: `CLAUDE_CODE_REMOTE=true .claude/hooks/session-start.sh`). PokeAPI data and sprites are reachable through `raw.githubusercontent.com` (not `pokeapi.co`).

## Design rules (owner's, 8 November 2026)
Read `docs/pokelife/FEATURES/DESIGN_SYSTEM.md` sections 5.1 and 12A before any UI change. **Every module's main screen has one order, always (owner, 20 November 2026): a short lead box, an overview of the module's main records (the task list, the accounts and budget), the action items in a "Quick actions" box (add a task, add an expense), then the party last; the module's places are reached from the header's Sections key, not from a row of keys on the page.** In short: every big section sits in a dialogue box; every control is pixel-drawn with stair corners (`PixelField`, `PixelToggle`, `PixelSlider`, `PixelBar`; no Material rounded parts); module colours follow the rainbow table (Pokégear on top, World at the bottom, red is not chrome); the buddy shows on Home only; a row's contents share one centre line; and no caption that restates what is on the screen (empty states are a title and one action, menu cards an icon and a title). Look at a real screenshot in both palettes before calling a screen done: one per state a change adds (a toggle on and off, a filter, an empty state), with the longest label that state can show, and check no text is clipped (a fixed-height tile clipped the PC's place line in 0.180.0).

## Swarm workflow and token use
Why the rules below: every request resends the whole context, and a cold cache costs about 20 to 25 times a warm one. So keep sessions short and single-topic, never switch model, effort or fast mode mid-session, and keep big files and noisy output out of context. Research and numbers: the token-optimization report of 15 November 2026.
- **Model and effort (owner, 15 November 2026):** choose once at session start and keep it. Sonnet 5.5 for implementation and routine work; Opus 5.5 for game-rule, economy, migration and sealed-data sessions. The advisor (`/advisor`, set to Opus) covers judgment calls. No `opusplan`, no mid-session `/model`, no fast mode on unattended runs. `/clear` between unrelated tasks; `/compact <focus>` only at a natural break.
- **Project agents** (`.claude/agents/`, each pinned to a model, effort and a minimal tool set; pick one by name as `subagent_type`):
  - `scout` (Haiku, read-only): where is X used, what does this file or screen do. Answer with `path:line`.
  - `spec-reader` (Haiku, read-only): pull the rules out of one `docs/pokelife/` or `docs/design.md` section and report them with their section numbers.
  - `builder` (Sonnet): one scoped code edit plus its targeted check; never commits.
  - `docs-writer` (Sonnet): changelog, backlog, design, economy and code-map updates from a brief; takes the next free `VERSION`; never commits.
  - `gate` (Haiku): runs a Gradle command and returns only PASS/FAIL and the first errors.
  **Always delegate, without being asked (owner, 15 November 2026):** every Gradle gate or long build goes to `gate` (never run the full gate in the main session: the log stays out of context); a search that would take three or more greps, or a spec lookup of more than one section, goes to `scout` or `spec-reader`; the record-keeping for a finished change (changelog, backlog, code-map, VERSION) goes to `docs-writer` once it touches more than two files. Everything else follows the rule below, and a user's "use subagents" never means forcing one onto a small edit.
  Delegate only when it saves context: a broad search, a spec lookup, a long build, or independent edits in parallel. A task you can finish in a few tool calls you do yourself; a cold sub-agent re-reads what you already know. Game-rule and economy decisions and the final review stay in the main session. Give each sub-agent a self-contained prompt (files, goal, what to return), run independent ones in parallel, ask for short reports, and check them before reporting done. Sub-agents do not call the advisor.
- **Advisor:** call `advisor` once after orienting and before writing code, for game-rule and economy changes, schema migrations, anything touching sealed Heal or Mint data, and new module work. Skip it for UI tweaks, tests, docs and one-line fixes. For repo-wide checks it is optional. Each call re-reads the whole transcript uncached, so call it early, not late.
- Search before reading, and read only the line ranges you need (`offset` and `limit`). A hook (`.claude/hooks/guard-read.sh`) blocks reading a text file over 32 KB in one go: grep for the heading, then read a range.
- Never read these whole: `pokemon-core/src/commonMain/resources/dex/*.json` (about 900 KB: grep the species or form), `docs/design.md` (90 KB), `docs/economy.md` (52 KB), `docs/world-economy-report.md`, `docs/world-story-*.md`, `docs/ASSETS/`, `docs/code-map.md`, `docs/region-candidates.md`, `docs/pokelife/IMPLEMENTATION_BACKLOG.md` (36 KB), everything else under `docs/pokelife/` (about 930 KB: read `README.md` and the Product Bible, then grep headings and read one section), `rip/` (about 52 MB of the Explorers of Sky rip: read `rip/sky/README.md`, then grep), `kotlin-js-store/yarn.lock`, the `databases/*.db` files (denied), and `CHANGELOG.md` beyond its newest entry. Never list `assets/sprites`, `assets/animated`, `assets/pmd` or `assets/cries` (thousands of files); grep their `.tsv` manifests.
- Images cost tokens: open a `ScreenshotTest` PNG or a sprite only for the screen or Pokémon you changed, never a whole folder.
- Gradle output is long: run builds and tests with `--console=plain` and trim to what matters, e.g. `./gradlew jvmTest --console=plain 2>&1 | grep -E "FAILED|BUILD|e: |Test.*>" | head -40`, or hand the run to `gate`. Re-run only the failing module or class (`--tests`). Run the slow ones (`simulateEconomy`, `assembleDebug`, the wasm build) only when the change needs them, in the background where you can. Shell output is capped at 15,000 characters (`bashOutputMaxChars`).
- Repo-wide checks ("is everything still good"): `gate` for the build and test commands, one `scout` per module for docs-versus-code drift; the main session only collects the short reports.
- Leave `legacy-android/` alone unless the task is about it. Keep replies short and skip restating the diff.

## Compact instructions
When compacting, keep: the task and its backlog id, the branch and `VERSION`, decisions the owner made this session, files changed and why, failing tests with their first error line, open questions. Drop: file contents already read, search output, Gradle logs, abandoned approaches.


## Parallel sessions (the owner runs several at once)
Sessions start from "continue with the next chunk", so two can pick the same one (LINK was built twice, 7 to 8 November 2026). The session-start hook prints what other sessions have pushed and not merged (`.claude/hooks/in-flight.sh`, last 3 days, with each branch's first commit, the folders it touches and its `VERSION`). Run it again by hand any time; `in-flight.sh <word>` filters.
- **Pick** the first backlog item (`docs/pokelife/IMPLEMENTATION_BACKLOG.md`, then the guide's order) that no in-flight branch or recent merge on `main` already covers. When in doubt, read that branch's commits (`git log origin/<branch> --not origin/main`) before starting.
- **Claim it as your first action**, before reading code: `.claude/hooks/claim.sh "<backlog id> <topic>"` checks the other branches for the same words (exit 2: pick another), then pushes an empty `claim: ...` commit on your session branch so every other session sees it. `FORCE=1` only for a chunk that is really different. If you drop the chunk or find it done elsewhere: `claim.sh --release "why"`.
- **Re-check before the PR:** `git fetch origin main`, run `in-flight.sh` again, and merge `main` in. If `main` or another branch now has the same work, stop and say so instead of merging a duplicate; port only what is missing. Two branches with the same `VERSION` collide: take the next free number after fetching, just before the PR.
- Touching a file many sessions edit (`CHANGELOG.md`, `IMPLEMENTATION_*`, `GameStore.kt`, `App.kt`)? Merge `main` in early and often; add your lines at the end of a section so conflicts stay trivial.

## Working rules (from the 12 November 2026 session review)
- **Asking the owner for a decision:** write each question as a standalone item: what it is (the screen or feature, in plain words, no shorthand from earlier in the session), why it matters in one sentence, two or three lettered options, and your recommendation. Number them so one reply ("1A 2C") answers all. For one the owner leaves unanswered, use the recommendation and say so in the PR body under "Defaults applied". Gather every open question into one list before building, not one at a time.
- **Standing request from the owner (15 November 2026): when a session's work is done, load the `ship-pr` skill and open the PR and merge it, without waiting to be told.** This is the owner's explicit, lasting ask, so it satisfies a cloud session's default "open a PR only when asked"; the owner has had to repeat it every session. Ask first only for something risky (a schema migration, a store cutover, sealed Heal or Mint data) or when the gate fails.
- **Gate, merge, scope:** while working run only targeted tests; run the full `./gradlew jvmTest compileKotlinWasmJs` once on the merged head just before the PR. "Merge" means all of it: commit, push, merge `main` in (next free `VERSION`), gate, open the PR, merge it when clean, say what merged. One PR per session, a commit per item; split off a separate PR only for something risky or urgent. Full text: `ship-pr` skill.

## Sessions and handoff
- One session per topic (a roadmap item, or a batch of fixes from phone testing). Start a new session rather than continuing a long one: every turn resends the whole conversation, so a long session costs more for each step.
- When the topic is done (its PRs merged, or open and green), Claude ends with a **handoff prompt** the owner pastes into the next session: what shipped (PR numbers), what is still open and its state, decisions waiting on the owner (deploys, merges), and the next item with where its spec lives. It does not repeat what this file, the skills or the docs already say.
- `docs/pokelife/IMPLEMENTATION_BACKLOG.md` and `CHANGELOG.md` are the record of progress: keep them current, so a new session needs nothing else.

## Branches and pull requests
**Load the `ship-pr` skill before opening, updating or merging a PR.** The essentials:
- `main` is the stable branch: never push to it (a settings deny enforces it); every change reaches it through a pull request.
- A cloud session works on the branch it was handed (`ccr-…`, `claude/…`) and pushes only there. If its PR is already merged, restart the same branch from the latest `main`. Hand-made branches match `^(feat|fix|content|design|chore|docs)/(auth|home|focus|tasks|pokedex|party|settings|data|ui|build|repo|care|heal|mint|link|gear|world)-[a-z0-9]+(-[a-z0-9]+)*$`.
- Before the PR: fetch and merge `main`, run `./gradlew jvmTest compileKotlinWasmJs`, read the diff once more. Title `<type>(<area>): <what changed>`, sentence case, no final period.
- Merge it (a merge commit) once CI is green on the latest commit and there is no conflict. CI red only for a failure that is not in the PR's change, with the local gate passing: merge anyway after one comment saying which check and why.
- If Actions cannot run because of billing (checks fail to start, not a red test), CI is not a gate: run the gate locally, merge, then build the APK by hand with a build number and send it with `SendUserFile` (procedure in `ship-pr`).
