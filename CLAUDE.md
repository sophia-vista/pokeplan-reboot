# PokéLife (reboot)

**`docs/pokelife/` is the source of truth** for what PokéLife is and what to build (owner, 6 November 2026): start at `docs/pokelife/README.md`, then the Product Bible and the module or feature spec you are touching. `docs/design.md`, `docs/ecosystem.md` and `docs/economy.md` describe what the code does today and are evidence, not authority; where they disagree with `docs/pokelife/`, it wins, and a rule changes in the owning `docs/pokelife/` file first. Decisions already made there: Android is the only product platform (desktop and web are dev conveniences that gate nothing); local-only has priority (no new Supabase, account or sync work; they are retired after the migration gates); the modules are PLAN, CARE, HEAL, MINT, HOME, LINK, GEAR and WORLD (no Grow, no Explore); one currency, Poké; and a Pokémon in **one place only** (7 November 2026): the global buddy (the main companion, cosmetic), a party of one lead and five per module (its bonuses apply to that module only), a Guardian slot, a WORLD expedition team, a GEAR helper (visual only), or the PC (`Places` in app-core; every assignment takes the Pokémon from its old place). `docs/pokelife/IMPLEMENTATION_BACKLOG.md` is the work list.

The app is **PokéLife** (renamed from PokéPlan in 0.47.0; PokéPlan is now the name of its Plan module). Code packages (`app.pokeplan.*`), the repository, the Android application id and the save keep the old name. A fun productivity, growth and self-improvement app for Pokémon lovers: finishing a focus timer hatches an Egg, finishing tasks, habits and goals earns candies and items that level up and evolve Pokémon. The repo holds two codebases:

- **The rewrite (repo root):** Kotlin Multiplatform (Android, desktop, web), local-only (the Supabase backend was retired in 0.130.0). `docs/pokelife/` says what to build; `docs/design.md` records the game rules the code implements today. Read the relevant `docs/pokelife/` spec before changing game rules, and update it (and `docs/design.md` when the code changes) when a rule changes. Numbers marked *(tune)* there are starting values.
- **The original app (`legacy-android/`):** a native Android Java app from a MOBDEVE pair project, kept as the reference for the old rules. It is no longer developed.

## Layout
- `pokemon-core/`: the Pokémon side, reusable by every app in the planned family (see "Platform and apps" in docs/design.md); Kotlin Multiplatform (JVM and wasmJs), no UI, knows nothing about tasks or focus. Packages under `app.pokeplan.core`: `dex` (the National Dex: species, forms, evolutions, regional dexes, Pokédex text, types, rarity, egg rarity tables and hatch rules; `dex/generated/DexData.kt` is generated), `reward` (the reward engine, candy reward tables, trainer rank), and `pokemon` (an owned Pokémon with IVs, EVs, nature, ability, gender, shiny, friendship; stat formula; hatching; items, bag, perks and transfer; candy, friendship and shiny rules; evolution rules; and the Guardian role of legendaries and mythicals in `Perks.kt`). `jvmMain/tools` holds JVM-only reports such as `./gradlew :pokemon-core:curationReport`.
- `care-core/`: the Care module's rules (routines, calm breaks, mood check-ins, prompts, trends; package `app.pokeplan.care`), JVM and wasmJs; its screens are `screens/Care.kt` (Modules → Care, `AppModel.care`, switched by `Settings.careModule`). It meets the game only through `CareEvent` (`RewardEngine.care`); `CareStore` in app-core keeps its own save and pays through the `World` interface (docs/ecosystem.md, section 6).
- `heal-core/`: the Heal module's rules (docs/pokelife `MODULES/HEAL.md` section 22): manual activity, hydration, sleep, body measurements and optional goals, units and trends in words, and what may pay Field Research (`HealRules`); JVM and wasmJs, no UI, knows nothing about Pokémon or rewards (package `app.pokeplan.heal`). `HealStore` in app-core keeps its own save (`HealData`) and pays through the `World` interface with the minimal `HealEvent` only; `HealReminders` is the hydration reminder source; its screens are `screens/Heal.kt` (Modules → Heal). The Heal Region is `tools/species/regions/heal.txt`; Heal's party is `PartyIds.HEAL`. **Heal's records are in `heal_*` tables from the start (schema 7, 0.136.0, `HealTables`, `LiveDocuments.moveHealToTables`), one family per private kind, never in the `save` document.**
- `mint-core/`: the Mint module's rules (docs/pokelife `MODULES/MINT.md` section 22): accounts, transactions, budgets, bills, reconciliation and review, exact integer-minor-unit money (`Money`), net position, available money, and what may pay Ledger Research (`MintRules`); JVM and wasmJs, no UI, knows nothing about Pokémon or rewards (package `app.pokeplan.mint`). `MintStore` in app-core keeps its own save (`MintData`) and pays through the `World` interface with the minimal `MintEvent` only (never a figure); its screens are `screens/Mint.kt` (Modules → Mint). The Mint Region is `tools/species/regions/mint.txt`; Mint's party is `PartyIds.MINT`. **Mint's records are in `mint_*` tables from the start (schema 8, 0.141.0, `MintTables`, `LiveDocuments.moveMintToTables`), never in the `save` document, and every row and every backup copy of Mint is sealed (AES-256-GCM, Android Keystore key: `RowCipher`, `AesGcmCipher`, `KeystoreMintKey`, `DataStore.mintCipher`; tables refuse to start without it).** Mint also has a passphrase-sealed portable backup (`PassphraseSealer`, `BackupBundle.portable`), bill reminders (`MintReminders`) and an optional screen-lock gate (`DeviceGate`) since 0.142.0. A new Pokémon arrives with the scene of its module (`Acquisition`, `Cutscenes.kt`): the egg only for Plan's eggs and a visitor's gift.
- `home-core/`: the Home module's rules (docs/pokelife `MODULES/HOME.md` section 16): chores and their deterministic schedules (`Schedules`, `HomeRules.view`: only the latest occurrence up to today, no backlog), supplies with exact quantities (`Quantity`, thousandths), assets, maintenance, warranties, reference notes, search, and what may pay Habitat Discovery (`HomeRules.chorePays`); JVM and wasmJs, no UI, knows nothing about Pokémon or rewards (package `app.pokeplan.home`). `HomeStore` in app-core keeps its own save (`HomeData`) and pays through the `World` interface with the minimal `HomeEvent` only (never a household word); its screens are `screens/Household.kt` (Modules → Home; `Place.HOUSEHOLD`, `Module.HOME`, `AppModel.home`). The Home Region is `tools/species/regions/household.txt` (`Region.HOUSEHOLD`); Home's party is `PartyIds.HOME`. **Home's records are in `home_*` tables from the start (schema 9, 0.143.0, `HomeTables`, `LiveDocuments.moveHomeToTables`), never in the `save` document; not sealed.**
- `link-core/`: the Link module's rules (docs/pokelife `MODULES/LINK.md` section 15): people and notes, important dates (`LinkRules.next`: annual or once, 29 February observed on the 28th in a year without one), follow-ups (only the title is required; `LinkRules.state`: Upcoming or Due, never a warning), search, duplicate suggestions that never merge, and what may pay Postcard Trail (`LinkRules.pays`); JVM and wasmJs, no UI, knows nothing about Pokémon or rewards (package `app.pokeplan.link`). `LinkStore` in app-core keeps its own save (`LinkData`) and pays through the `World` interface with the minimal `LinkEvent` only (never a person or a follow-up word); its screens are `screens/Link.kt` (Modules → Link; `Place.LINK`, `Module.LINK`, `AppModel.link`). The Link Region is `tools/species/regions/link.txt` (`Region.LINK`); Link's party is `PartyIds.LINK`. **Link's records are in `link_*` tables from the start (schema 10, 0.144.0, `LinkTables`, `LiveDocuments.moveLinkToTables`), never in the `save` document; not sealed.**
- `world-core/`: the World game's rules (docs/world.md): dungeons, expedition teams, the deterministic offline simulation, Exploration Finds, rank and the story as data; JVM and wasmJs, no UI. Its save is `AppData.world`, kept by `GameStore`'s `world*` functions; its screens are `screens/World.kt` (Modules → World). Not the same as the Explore module (trips and a travel journal) in docs/ecosystem.md.
- `data/`: the local database that will replace the JSON saves (docs/pokelife `ARCHITECTURE/DATA_AND_MIGRATIONS.md`, REP-008): SQLDelight on SQLite, Android and JVM targets only, package `app.pokeplan.data`. Schema in `src/commonMain/sqldelight/.../Data.sq`; every released schema is committed in `databases/N.db`, and `jvmTest` runs `verifyCommonMainDataDbMigration`, so a schema change needs a numbered `.sqm` migration. `DataStore` (foreign keys checked on open, one transaction coordinator), `PokemonRepository`, `EconomyRepository` (idempotent, append-only ledger) and `LegacyJsonImporter` (`save.json` and `care.json` in; not touched). **Live since 0.129.0 on Android (the cutover):** the app's two JSON documents (`save`, `care`) live in the table `live_document` (`LiveDocuments`, schema v2), activated once from `save.json` and `care.json` (which are then never written again, kept as the rollback copy), with a daily file backup of the documents (`LiveBackup`, `filesDir/backups/`, newest 3) and a move-aside-and-restore path for a corrupt file; the Android wiring is `androidApp/.../LiveStore.kt` behind `saveStorage()`/`careStorage()`. The normalized tables (Pokémon, Bag, ledger) were filled by the importer only until 0.135.0 and are now the live authority for the player's side of the save (below); desktop and web keep their JSON stores. The shared reminder feature stores its snoozes and repeats in `reminder_hold` (schema v3). **PLAN's records live in their own tables since 0.133.0 (schema v5):** `PlanTables` under `LiveDocuments`, which splits the `save` document into PLAN's part (`plan_*` tables) and the rest (the `save` row) and puts it back together on a read; `movePlanToTables` activates it once with read-back. **Care's records live in their own tables since 0.132.0 (schema v4, REP-014):** `CareTables` takes the Care JSON apart into `care_*` rows and puts it back together under the unchanged `CareStore`, and `LiveDocuments` routes the `care` document through them after `moveCareToTables` (read back, old row kept aside); **The shared Pokémon, Bag and ledger tables are live since 0.135.0 (schema 6, REP-014):** `PokemonTables` splits the player's part of the `save` document (the Pokémon, their places, the Dex history, the Egg meter and trainer points, the Bag and the Poké balance) from the rest, `movePokemonToTables` activates it once (the save first goes through `GameStore.normalizeDocument`, which `LiveStore` sets as `LiveDocuments.normalizer`; read-back compared, the old save kept as `aside:save:pokemon:<millis>`, the balances one opening-balance event), a Pokémon's place is at most one row of `pokemon_place` (primary key = the Pokémon; WORLD teams and GEAR helpers stay in the `save` row and the write refuses a Pokémon named there and in the table), the ledger is the only writer of the balance and the Bag (a live write settles the change of one save as one event), and `WorldData.poke` is never stored. The app still reads one `AppData` through the split; the typed repositories are not used by it yet (`DATA_AND_MIGRATIONS.md` section 7.3.0). Next: HEAL, and the typed repositories per module. Debug builds have a second icon, DB check (`DeviceSelfCheck`). Tests: `./gradlew :data:jvmTest`.
- `plan-core/`: PokéPlan's own logic (focus sessions now; tasks, habits, goals and the planner next). Depends on `pokemon-core`. Package `app.pokeplan.plan`.
- The buddy never chats: no permanent speech bubble, needs or mood meter; level and progress sit small in a corner, and one reaction (like a game emote) happens only for a real event or a tap (`GameStore.buddyEvent()`, an egg hatched or a payout in the last few minutes, celebrated once): an emoji for a tap, its SpriteCollab portrait for an event. It sleeps during focus and hops or eats with its own SpriteCollab animations (`SpriteAction`); `Portrait` and `SpeakerBox` show its face beside text.
- `DayBackground` (composeApp) is the default page behind every screen (`AppBackdrop` swaps in a real scene or dungeon town under a veil when Settings → Look → Background asks): an ordered-dither gradient with a light grain, drawn in code as UI chrome (not art) and tinted by the time of day; screens must not paint their own opaque background over it. Starred Pokémon (`AppData.favorites`) and the Shiny Dex (`AppData.shinySpecies`) are client-side data in the save, not in the server's game state.
- `assets/`: real game assets (sprites, animated sprites, cries, sound effects, scenes, item icons, type plates, PC box wallpapers, fonts), fetched by the scripts in `tools/sprites` and listed with their sources and licences in `docs/assets.md`. How each is fetched, regenerated and used, the Dex data generator and the module region curation kit: the `game-assets` skill.

- `legacy-android/`: the original Android Java app, no longer developed. Everything about it (commands, Firebase, architecture, the old rules) is in the `legacy-android` skill.
- `app-core/`: the app's rules engine with no UI (`GameStore` applies every user action with the real game rules and saves one JSON document through a `Storage`; `AppData` is the saved shape). JVM and wasmJs; its tests run with `./gradlew :app-core:jvmTest`.

- The bottom tabs are **Home / Modules / Pokémon / Me** (`Tab` in `App.kt`). Home, Pokémon and Me hold what every module shares; each life module is a section of Modules (`screens/Modules.kt`: `Module`, Plan's `PlanSection` with Planner, Focus, Growth, Goals and Review), and `AppModel.module` keeps the open one. `Place` is where the app can be sent (widgets, shortcuts and notifications name `PLANNER`, `FOCUS` and `CARE`).

Sprites (`assets/sprites`) and the Pokémon DS-era font (`assets/fonts`: `Pokemon-DP` and `-Bold` from the MIT-licensed hexparrot/pokemon-assets package for titles, buttons and numbers, used for body text too; the dialogue bitmap font `pmd-dialogue` (John2k4) for titles, labels and buttons) are copied into Compose resources by the `prepareComposeAssets` task; the generated `Res` is in package `pokeplan.composeapp.generated.resources`. Bump `VERSION` in the PR that ships something and add it to `CHANGELOG.md`.

Private repo only; TODO before any public release: move to a secret key.

Needs an Android SDK (`sdk.dir` in the git-ignored `local.properties`, or `ANDROID_HOME`) with `platforms;android-37.0` and build tools. `composeApp` sets `androidResources { enable = true }`, without which the APK ships without sprites, icons or fonts.

## Commands (rewrite, from the repo root)
- All tests (JVM): `./gradlew jvmTest`; one module: `./gradlew :pokemon-core:jvmTest`; one class: `./gradlew :pokemon-core:jvmTest --tests "app.pokeplan.core.EggTest"`
- Compile the web target: `./gradlew compileKotlinWasmJs` (wasm tests need yarn and a browser and are not run here)
- Regenerate Dex data: `python3 -I tools/species/generate.py`
- The golden vector (`pokemon-core/src/jvmTest/resources/golden.json`, checked by `GoldenVectorTest`): regenerate with `UPDATE_GOLDEN=1 ./gradlew :pokemon-core:jvmTest --tests "*GoldenVectorTest*"` after a deliberate rule change (and bump `RewardRules.VERSION`).
- **Actions are used sparingly (owner's rule, 6 November 2026):** `ci.yml` runs on a PR only with the `ci`, `android` or `apk` label (or by hand); `release-apk.yml` skips merges that change only docs, notes or `legacy-android/`. The local `./gradlew jvmTest compileKotlinWasmJs` is the normal gate. Apply `ci` to a PR only when its change really needs the runner.
- CI (`.github/workflows/ci.yml`) runs, when asked for as above, on a PR that changes more than text (a PR touching only `docs/`, `.md` files, `.claude/` or `legacy-android/` is not tested), and only there (not again on `main` after a merge; a newer push to a PR cancels the older run), as one job to save Actions minutes: the cheap checks first (VERSION, regenerating the Dex data changes nothing), then the JVM tests and the wasm build, then the Android app is **compiled** only when the PR touches `androidApp/`, an `androidMain` source set or the Gradle files (or has the `android` label). An APK is packaged, and kept as an artifact for 3 days, only for a PR with the `apk` label. It shares its Gradle cache key with the release workflow, so a PR starts from the last merge's downloads (check the "Cache" lines of a run to see whether that works).
- `.github/workflows/release-apk.yml` publishes every merge to `main` as the "latest" GitHub release with `pokeplan.apk` (debug build, shared signing key), so the newest app can be installed from a phone.
- World economy simulation: `./gradlew :world-core:simulateWorldEconomy` writes `docs/world-economy-report.md` (floors, jobs, facilities, Café, Swap Shop, Dojo, shop over a year); re-run it after changing any World number.
- Economy simulation: `./gradlew :plan-core:simulateEconomy` writes `docs/economy-report.md` (about 1 to 2 minutes). Re-run it after changing any reward, rank, egg, candy or transfer number and compare with the pacing targets in docs/design.md.
- Android app: `./gradlew :androidApp:assembleDebug` (APK in `androidApp/build/outputs/apk/debug/`). Desktop: `./gradlew :composeApp:run`. Web: `./gradlew :composeApp:wasmJsBrowserDevelopmentRun`. Compile checks without a display: `./gradlew :composeApp:compileKotlinJvm :composeApp:compileKotlinWasmJs`.
- Gradle 9.8.1, Kotlin 2.4.21, AGP 9.4.1, Compose Multiplatform 1.12.2, any JDK 17 to 21.
- In the cloud sandbox: `dl.google.com` (Google's Maven and the Android SDK) must be in the environment's allowed domains. The SessionStart hook (`.claude/hooks/session-start.sh`, cloud sessions only, no tokens spent, runs in the background) installs the SDK to `~/android-sdk` (cmdline-tools, `platform-tools`, `platforms;android-37.0`, `build-tools;37.0.0`), writes `local.properties`, and adds a Gradle init script in `~/.gradle/init.d` that tries `https://maven-central.storage-download.googleapis.com/maven2` first, because Maven Central rate-limits the shared proxy. **Before the first Gradle command of a cloud session, run `.claude/hooks/wait-for-setup.sh`**: it returns at once when the hook is done, waits while it runs, and says so if it failed (then run the hook by hand: `CLAUDE_CODE_REMOTE=true .claude/hooks/session-start.sh`). PokeAPI data and sprites are reachable through `raw.githubusercontent.com` (not `pokeapi.co`).

## Design rules (owner's, 8 November 2026)
Read `docs/pokelife/FEATURES/DESIGN_SYSTEM.md` sections 5.1 and 12A before any UI change. In short: every big section sits in a dialogue box; every control is pixel-drawn with stair corners (`PixelField`, `PixelToggle`, `PixelSlider`, `PixelBar`; no Material rounded parts); module colours follow the rainbow table (Pokégear on top, World at the bottom, red is not chrome); the buddy shows on Home only; a row's contents share one centre line; and no caption that restates what is on the screen (empty states are a title and one action, menu cards an icon and a title). Look at a real screenshot in both palettes before calling a screen done.

## Swarm workflow and token use
- For a large task, plan first, then split it. Simple subtasks (reading files, searches, formatting, quick checks) go to Haiku sub-agents (`model: "haiku"`); moderate ones (routine code edits, drafting, a test for an existing rule) to Sonnet sub-agents (`model: "sonnet"`). Planning, game-rule and economy decisions, and the final review stay in the main session at high effort. Small tasks are done directly, with no sub-agents.
- Sub-agents start cold: give each a self-contained prompt (files, goal, what to return). Run independent ones in parallel. Ask for short reports (the answer, not file dumps), and check their output before reporting it as done.
- Search this file (`Grep`) instead of rereading it. Search before reading, read only the line ranges you need (`offset` and `limit`), and don't reread a file you just edited.
- Never read these whole: `pokemon-core/.../dex/generated/DexData.kt` (generated, about 340 KB: grep the species or form), `docs/design.md` (about 50 KB: grep its headings, then read that section), everything under `docs/pokelife/` (about 700 KB: read `README.md` and the Product Bible, then grep headings and read one section), `docs/ecosystem.md`, `docs/ui-ux-brief.md`, `docs/region-candidates.md`, `supabase/README.md`, `kotlin-js-store/yarn.lock`, and `CHANGELOG.md` beyond its newest entry. Never list `assets/sprites`, `assets/animated`, `assets/pmd` or `assets/cries` (thousands of files); grep their `.tsv` manifests.
- Images cost tokens: open a `ScreenshotTest` PNG or a sprite only for the screen or Pokémon you changed, never a whole folder.
- Gradle output is long: run builds and tests with `--console=plain` and trim to what matters, e.g. `./gradlew jvmTest --console=plain 2>&1 | grep -E "FAILED|BUILD|e: |Test.*>" | head -40`. Re-run only the failing module or class (`--tests`). Run the slow ones (`simulateEconomy`, `assembleDebug`, the wasm and JS builds) only when the change needs them, in the background where you can.
- Send broad searches (where is X used, which screens show Y) to an Explore or Haiku agent. Leave `legacy-android/` alone unless the task is about it.
- Keep replies short and skip restating the diff.

## Sessions and handoff
- One session per topic (a roadmap item, or a batch of fixes from phone testing). Start a new session rather than continuing a long one: every turn resends the whole conversation, so a long session costs more for each step.
- When the topic is done (its PRs merged, or open and green), Claude ends with a **handoff prompt** the owner pastes into the next session: what shipped (PR numbers), what is still open and its state, decisions waiting on the owner (deploys, merges), and the next item with where its spec lives. It does not repeat what this file, the skills or the docs already say.
- The roadmap (`docs/ecosystem.md`, section 8) and `CHANGELOG.md` are the record of progress: keep them current, so a new session needs nothing else.

## Branches and pull requests
Adapted from the Balai Yllana website repo's workflow.
- `main` is the stable branch. Don't push to it directly (the one exception is the first "Initial commit"): every change reaches it through a pull request.
- **Every change starts a new branch from the latest `main`** (`git fetch origin main && git checkout -b <name> origin/main`), even a one-word fix. **One PR per session (owner's rule, 6 November 2026): bundle everything a session does, several backlog items included, into one branch and one PR, and run the full local gate and merge once at the end, not after each item.** Commit per item inside the branch so the history stays readable. Split off a separate PR only for a change the owner may want to revert on its own (a risky migration, a store cutover) or one that cannot wait for the rest. Never reuse a branch whose PR is merged or closed.
- **Branch names:** `<type>/<area>-<topic>`, lowercase, words joined with hyphens, the topic 1 to 4 words. It must match `^(feat|fix|content|design|chore|docs)/(auth|home|focus|tasks|pokedex|party|settings|data|ui|build|repo)-[a-z0-9]+(-[a-z0-9]+)*$`.
  - Types: `feat` (new behaviour or screen), `fix` (something broken), `content` (Pokédex entries, FAQ text, rarity and reward tables, strings), `design` (layouts, styles, drawables), `chore` (dependencies, Gradle, cleanup), `docs` (CLAUDE.md, README, comments).
  - Areas: `auth` (login, register, starter pick), `home`, `focus` (timer, eggs, Deep Focus), `tasks` (planner, reminders, candy rewards), `pokedex`, `party` (party, PC, levelling, evolution), `settings` (settings and profile), `data` (`DatabaseHelper`, Firebase, models), `ui` (shared widgets and navigation), `build` (Gradle, Firebase config, CI), `repo` (everything else). A change that touches several areas but serves one takes that area; otherwise `ui` or `repo`.
  - Examples: `fix/focus-deep-focus-threshold`, `content/pokedex-gen-three`, `feat/tasks-recurring-reminders`, `chore/build-upgrade-agp`.
- **Claude sessions** follow the same convention. A cloud session is handed an automatic branch name (`ccr-…`, `claude/…`); ignore it and create a correctly named branch from the latest `main` instead. Never push to `main`.
- **After the changes, open a PR** into `main`: bring in the latest `main` first, run `./gradlew jvmTest compileKotlinWasmJs` from the repo root (and `testDebugUnitTest assembleDebug` from `legacy-android/` only if you touched it), and read the diff once more. Title: `<type>(<area>): <what changed>`, sentence case, no final period, e.g. `fix(focus): Reset the timer when the screen turns off`. **Once CI is green on the PR's latest commit and it has no merge conflict, Claude merges it (a merge commit)** (the owner's standing rule; the cloud sandbox cannot delete remote branches, so GitHub's "Automatically delete head branches" setting or the owner removes them); while CI is red because of the PR, Claude fixes it first. **If CI is red only for a failure that is not in the PR's change (the same check is red on `main` or on other PRs, or a test that passes locally fails on the runner) and `./gradlew jvmTest compileKotlinWasmJs` passes locally, Claude merges anyway** (the owner's rule, November 2026), after one comment on the PR saying which check and why it is not the PR's.
- **If GitHub Actions cannot run because of billing** (the checks fail to start or the run says the account is locked or payments failed, not a red test), CI is not a gate: run `./gradlew jvmTest compileKotlinWasmJs` locally instead, merge the PR once those pass and it has no conflict, and **end the session by building the APK by hand with a build number**, since `release-apk.yml` will not run. Use `POKEPLAN_BUILD=<N> ./gradlew :androidApp:assembleDebug`, where N is one more than the build in the title of the newest "Latest build (vX.Y.Z, build N)" release (`list_releases`), and send `androidApp/build/outputs/apk/debug/` `*.apk` to the owner with `SendUserFile`, saying the version and build number. The handoff prompt says Actions was down, so the owner knows the release was not published and the next build number may need correcting.
